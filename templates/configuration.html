Download bandwidth

Set your connection’s practical maximum across all downloads, for example 28 MB/s. During a manual run, adaptive downloads add one file at a time when measured total speed stays below 95% of this target for a 30-second observation window. The target is not a speed cap. Changes apply to the running queue within five seconds. Adaptive mode favors other data centers when a file is slow. Slow transfers keep running; completed releases can be extracted and moved first. Split archives wait for their parts. Disabling adaptive mode lets active transfers finish before returning to one file. Saving settings never starts a new run.

Download servers

Auto (fastest) compares real download speed. Reusing recent results avoids repeated test delays. You can also compare before each artist’s monthly release and reuse the choice for its files and archive parts.

Per-release tests use two-second samples per server, plus connection setup. A comparison can take more than ten seconds. Manual server choices skip these tests. Auto compares after 2 minutes below this threshold, before the next large file. Below half the threshold, it pauses the current file and compares immediately, then resumes with its saved chunks. Both rules use a 30-second average after a 10-second warmup, with at most one slowdown comparison per 10 minutes. While files overlap, checks use their combined speed. The counter carries across files and releases; extraction, moves and idle time pause it. Set 0 to disable. Telegram stores files in specific data centers. You can choose a server separately for each one. Small files use a cached result or a media server until a larger file can be tested.
